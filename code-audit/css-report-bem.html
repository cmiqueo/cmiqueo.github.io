1. Summary

Measured against strict BEM, essentially the entire authored codebase is non-compliant on naming — but not because of scattered mistakes. The project deliberately uses a SUIT-CSS-style convention that is internally consistent yet structurally different from BEM on every point. So virtually every component, card, infobit, and filter file is flagged Inconsistent on the naming axis, even where it is otherwise clean.

Ironically, a few of the presentational one-offs the codebase would normally frown on — .filters-category--icon (categories.less), .modern-carousel--light (cards-carousel.less) — are among the closest things to valid BEM in the repo, because they pair a kebab block with a -- modifier.

Bottom line: this is not a BEM codebase. If BEM is the target, the finding is a wholesale convention mismatch — adopting it would mean renaming nearly every selector across the bundle and its consuming AEM/DEXTER markup.

2. Systemic & Recurring Issues

  1. Single-hyphen elements instead of __ (repo-wide). Every consonant component uses &-element (.consonant-Card-inner, .consonant-LeftFilter-itemsItemName). BEM requires card__inner. This alone makes ~50 files non-compliant.
  2. PascalCase (prefixed) blocks instead of kebab-case. .consonant-Card, .consonant-FiltersInfo, .consonant-BtnInfobit… BEM wants .card, .filters-info.
  3. is- state classes are not BEM. .is-active, .is-opened, .is-selected, .is-loading, .is-disabled throughout. BEM expresses state as a modifier.
  4. camelCase modifiers instead of kebab-case. --withFilters, --overBg, --negMargin, --autoWidth, --2up — separator right, casing wrong.
  5. Variant classes chained onto a block instead of modifiers. .consonant-Card.three-fourths, .one-half, .full-card, .news-card, .half-height. BEM would use card--three-fourths.
  6. Hardcoded hex/rgba colors instead of tokens (standard, not naming): cards-carousel .modern-carousel (~15), categories (~14), blade, editorial, button, flex (#333/#666), pagination/select (#999/#ccc/#aaa), accessibility (#dedede), filters/left/panel (#eaeaea/#fff).
  7. Two competing color-variable systems. cards/icon.less and cards/horizontal.less use the static @consonantLightGrey*/@consonantDarkGrey* palette instead of themeable @consonantGray* → ignore theming.
  8. Raw-px / arithmetic media queries bypass named queries: cards-carousel (599px + 1), cards-grid (320/600), categories (480), blade (1200/600). utils/hide.less references two undefined vars (@for-tablet-portrait-up, @for-desktop-up).
  9. Duplicated helpers & dead code. .no-font/.margin-auto/.full-width/.hide-all defined in both utils//references/ and components/consonant/utils.less; .hide-all 3× in hide.less; dead blocks in lineclamp.less:15-37, utils.less, filters/left/item.less:476.
  10. Genuine selector bugs (standard-agnostic). &-element misuse in variant scopes (three-fourth:90, text:87, double-wide:136,140,150,154, editorial:22-26); bare :only-child (half-height:92,143, double-wide:51,87); missing comma in search.less:57-59; typos --83PercentContainier, &-selctedItemsQty; mis-scoped leaks in news:26-51, three-fourth:241.
  11. The only near-BEM naming is accidental: categories.less (.filters-category--icon) and cards-carousel (.modern-carousel--light) pair a kebab block with a -- modifier — the closest the repo comes to BEM, though both are riddled with hardcoded colors.

4. Recommendations

Because the audit standard (BEM) and the codebase convention (SUIT-CSS-style) fundamentally disagree, recommendations split into two tracks.

Track A — Decision first (most impactful)

Confirm the intended standard. The codebase is coherently SUIT-CSS-style and shipped into AEM/DEXTER markup that references these exact class names. A true BEM migration (.consonant-Card-inner → .card__inner, .is-active → --active, etc.) would touch nearly every selector and every consuming template — a large, breaking, cross-repo effort. If BEM is genuinely required, scope it as a dedicated migration with a class-name mapping and AEM-author coordination; do not attempt it piecemeal. If not, re-run this audit against SUIT CSS or the existing convention for an actionable punch-list.

Track B — Standard-agnostic fixes (worth doing regardless)

  1. Correctness (broken/dead rules): fix &-element-in-variant selectors (three-fourth:90, text:87, double-wide:136,140,150,154, editorial:22-26); bare :only-child (half-height:92,143, double-wide:51,87); missing comma in search.less:57-59; re-scope news:26-51 and three-fourth:241; typos --83PercentContainier, rtl.less:170; undefined @for-* vars in hide.less; invalid font-weight:light, outline shorthand, border:2px.
  2. Theming integrity: move icon.less and horizontal.less onto themeable @consonantGray*; replace hardcoded hex/rgba in cards-carousel, categories, blade, editorial, button, flex, filters/*, pagination, select, accessibility with tokens.
  3. Breakpoints: replace raw-px/arithmetic queries in cards-carousel, cards-grid, categories, blade with named @consonant-*-up queries.
  4. Hygiene: de-duplicate helpers across utils//references//components/consonant/utils.less; remove dead commented blocks (lineclamp:15-37, utils.less, filters/left/item:476); resolve the categories.less "should be moved" TODO; exclude vendor modal.less from future audits.
