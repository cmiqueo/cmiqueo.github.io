1. Summary

The codebase is internally disciplined around a consonant-PascalCase block convention with &-camelCase descendant nesting and &--camelCase modifier nesting — a close cousin of SUIT CSS, but the consonant- prefix itself is a deviation from bare SUIT (.FiltersInfo, not .consonant-FiltersInfo), applied consistently enough that it reads as an intentional house standard rather than an accident.

The real problems are concentrated in the cards/ folder and a handful of outlier files: card "type" selectors use inconsistent bare kebab-case classes instead of a single SUIT modifier, several files hardcode colors/sizes that already exist as variables, and 7 files (less/references/*.less, less/utils/*.less) are dead code — never @imported by the sole build entry point less/app.less.

2. Systemic & Recurring Issues

  1. The consonant- prefix breaks strict SUIT component naming, but is applied uniformly. Every block is .consonant-<PascalName> (e.g. .consonant-FiltersInfo, .consonant-LeftFilter) rather than a bare .FiltersInfo. This is the single most common "deviation" in the audit, appearing in nearly every file — but because it is applied consistently, it reads as the project's real baseline rather than noise. Recommend documenting it explicitly as the project convention rather than treating each instance as an error.
  2. Card "type" modifiers are bare, inconsistently-named kebab-case classes instead of a single SUIT modifier. cards-grid.less/theme.less key off .consonant-Card.one-half, .blog-card, .button-card, .editorial-card, .flex-card, .double-wide, .product, .text-card, .three-fourths, .horizontal-card, .icon-card, .news-card. Naming isn't even consistent among themselves (-card suffix vs. none, singular vs. plural: three-fourths vs double-wide vs product). Under SUIT this should be one scheme, e.g. .consonant-Card--oneHalf.
  3. Duplicated near-identical blocks instead of shared mixins. filters/left/item.less (601 lines) and filters/top/item.less (568 lines) are ~90% structurally identical (checkmark, badge, footer, category-nesting logic all repeated). Likewise filters/left/panel.less and filters/top/panel.less. The card-banner/badge/logo block (~30 lines) is copy-pasted near-verbatim across full.less, half-height.less, one-half.less, text.less, three-fourth.less, flex.less, double-wide.less.
  4. Widespread magic numbers and hardcoded colors instead of variables.less/theme.less tokens. Worst in cards-carousel.less (hex colors #242424, #e6e6e6, #d5d5d5, #b1b1b1, plus pixel widths 500px/394px/389px/384px/378px duplicating values that exist as variables elsewhere), cards/blade.less, cards/button.less, cards/flex.less, and categories.less.
  5. Dead code: 7 files are never imported by the build. less/app.less only imports components/consonant/main.less, whose import chain covers every components/consonant/*.less file but never reaches less/references/flex.less, references/main.less, references/type.less, utils/hide.less, utils/lineclamp.less, utils/margin.less, or utils/misc.less. These duplicate functionality already present in components/consonant/utils.less (.hide-all, .line-clamp(), .margin-auto, .full-width) and, notably, references/main.less/type.less use presentational class names (.left, .center, .right, .bold) that would themselves fail this audit's "no presentational names" rule if they were ever compiled.
  6. Ad-hoc breakpoints bypass the shared breakpoint variables. cards-grid.less (@media (max-width: 320px), (max-width: 600px)) and cards/blade.less (1200px, 600px) use raw pixel media queries instead of the @consonant-*-up/-down variables defined in media-queries.less and used everywhere else.
  7. modal.less is a vendored style island. It opens with /* stylelint-disable */, uses 2-space indentation (vs. 4-space everywhere else), and follows an entirely separate dexter-/kebab-case naming system, making it visibly inconsistent with the rest of the authored tree even though its third-party origin explains why.
  8. Isolated copy/paste bugs. rtl.less has a typo, &-selctedItemsQty (missing an "e"), under .consonant-TopFilter — this RTL rule never matches the real class consonant-TopFilter-selectedItemsQty emitted by Filters/Top/Group.jsx, so it silently does nothing. search.less has a multi-line transition list missing a comma between border-color … and background-color …. cards-carousel.less mixes uppercase and lowercase hex in inline SVG fills (%23B1B1B1 vs %23b1b1b1).

4. Recommendations

Priority 1 — Highest impact

  • Standardize card "type" modifiers on a single SUIT scheme. Replace the mixed bag of .one-half, .blog-card, .button-card, .product, .three-fourths, .double-wide, .icon-card, etc. with one convention (e.g. .consonant-Card--oneHalf). Touches the largest number of files (cards/, cards-grid.less, theme.less, rtl.less) — coordinate with the React/AEM markup that emits these class names.
  • Remove or wire up the 7 orphaned files. Delete less/references/*.less and less/utils/*.less (hide/lineclamp/margin/misc) if truly unused, or @import them if they were meant to ship — right now they are dead weight that risks confusing future contributors who edit them expecting an effect.

Priority 2 — Structural cleanup

  • Extract the repeated card-banner/badge/logo/videoIco block into a shared mixin in utils.less, used by all card files, instead of the current ~30-line copy-paste across 7 files.
  • Consolidate filters/left/item.less + filters/top/item.less (and the matching panel.less pair) into shared mixins/partials — they are ~90% identical and drift risk is high (as evidenced by the rtl.less typo affecting only one of the two).

Priority 3 — Tokens & correctness

  • Replace hardcoded colors/sizes in cards-carousel.less, cards/blade.less, cards/button.less, cards/flex.less, and categories.less with existing variables.less/theme.less tokens; consider a stylelint rule forbidding raw hex/pixel literals in the Consonant tree going forward.
  • Fix the two concrete bugs found: the rtl.less &-selctedItemsQty typo (dead RTL rule) and the missing comma in search.less's transition list.

Priority 4 — Documentation

  • Document the consonant- prefix as the project's official naming standard (rather than pure SUIT) so future audits and contributors don't mistake a consistently-applied, deliberate prefix for an error.
