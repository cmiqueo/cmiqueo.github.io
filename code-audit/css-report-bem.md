# CSS Audit Report

**Project:** Adobe CaaS (Consonant Card Collection)
**Scope:** Authored LESS stylesheets under `less/` (68 files; `dist/`, `dependencies/`, `node_modules/` excluded)
**Date:** 2026-07-28
**Standard:** BEM — block `kebab-case`, element `block__element` (double underscore), modifier `block--modifier` / `block__element--modifier` (double hyphen, kebab-case). No `is-` state classes (in BEM, state is expressed as a modifier).

## 1. Summary

Measured against strict **BEM, essentially the entire authored codebase is non-compliant on naming** — but not because of scattered mistakes. The project deliberately uses a **SUIT-CSS-style convention** (`consonant-PascalCase` blocks, single-hyphen camelCase elements such as `&-btnSelected`, and `is-` state classes), which is internally consistent yet structurally different from BEM on every point: BEM requires kebab-case blocks, `__` element separators, and kebab-case `--` modifiers with no `is-` states. So virtually every component, card, infobit, and filter file is flagged **Inconsistent** on the naming axis, even where it is otherwise clean. Ironically, a few of the _presentational_ one-offs the codebase would normally frown on — `.filters-category--icon` (categories.less), `.modern-carousel--light` (cards-carousel.less) — are among the closest things to valid BEM in the repo, because they pair a kebab block with a `--` modifier. On top of the naming gap, the same formatting/standards issues from any lens remain: hardcoded colors, raw-px breakpoints, magic numbers, duplicated helpers, dead code, and several genuine selector bugs.

**Bottom line:** this is not a BEM codebase. If BEM is the target standard, the finding is a wholesale convention mismatch, not a punch-list of fixes — adopting BEM would mean renaming nearly every selector across the bundle and its consuming AEM/DEXTER markup.

## 2. Systemic & Recurring Issues

1. **Single-hyphen elements instead of `__` (repo-wide).** Every consonant component uses `&-element` (e.g. `.consonant-FiltersInfo-btnSelected`, `.consonant-Card-inner`, `.consonant-LeftFilter-itemsItemName`). BEM requires `filters-info__btn-selected`, `card__inner`, etc. This alone makes ~50 files non-compliant.

2. **PascalCase (prefixed) blocks instead of kebab-case.** `.consonant-Card`, `.consonant-FiltersInfo`, `.consonant-BtnInfobit`, `.consonant-LeftFilters`… BEM wants `.card`, `.filters-info`, `.btn-infobit`. The `consonant-` namespace itself is not a BEM concern, but the PascalCase component segment is a deviation.

3. **`is-` state classes are not BEM.** `.is-active`, `.is-opened`, `.is-selected`, `.is-loading`, `.is-disabled` appear throughout (bookmarks, filters, pagination, select, wrapper, card variants). BEM expresses state as a modifier (`block--active` / `block__el--active`), so all `is-` states are deviations.

4. **camelCase modifiers instead of kebab-case.** Modifiers use the `--` separator (BEM-correct) but camelCase names: `--withFilters`, `--withLightText`, `--overBg`, `--negMargin`, `--autoWidth`, `--2up`. BEM requires `--with-filters`, `--over-bg`, `--2-up`. Partial compliance (separator right, casing wrong).

5. **Variant classes chained onto a block instead of modifiers.** Card variants are kebab classes stacked on the block (`.consonant-Card.three-fourths`, `.one-half`, `.full-card`, `.news-card`, `.text-card`, `.half-height`, `.double-wide`). BEM would model these as `card--three-fourths` etc.

6. **Hardcoded hex/rgba colors instead of tokens** (standard, not naming). `cards-carousel.less` `.modern-carousel` (~15), `categories.less` (~14), `cards/blade.less`, `cards/editorial.less`, `cards/button.less`, `cards/flex.less` (`#333`/`#666`), `pagination.less`/`select.less` (`#999`/`#ccc`/`#aaa`), `accessibility.less` (`#dedede`), `filters/left/panel.less` (`#eaeaea`/`#fff`).

7. **Two competing color-variable systems.** `cards/icon.less` and `cards/horizontal.less` use the static `@consonantLightGrey*`/`@consonantDarkGrey*` palette instead of themeable `@consonantGray*`/`@consonantBaseColor`, so they ignore theming.

8. **Raw-px / arithmetic media queries** bypass the named-query set: `cards-carousel.less` (`599px + 1`), `cards-grid.less` (320/600), `categories.less` (480), `cards/blade.less` (1200/600). `utils/hide.less` references two **undefined** vars (`@for-tablet-portrait-up`, `@for-desktop-up`).

9. **Duplicated helpers & dead code.** `.no-font`/`.margin-auto`/`.full-width`/`.hide-all` etc. defined in both `utils/`/`references/` and `components/consonant/utils.less`; `.hide-all` 3× in `utils/hide.less`; dead commented blocks in `utils/lineclamp.less:15-37`, `components/consonant/utils.less`, `filters/left/item.less:476`.

10. **Genuine selector bugs (standard-agnostic).** `&-element` misuse inside variant scopes producing broken selectors — `cards/three-fourth.less:90`, `cards/text.less:87`, `cards/double-wide.less:136,140,150,154`, `cards/editorial.less:22-26`; bare `:only-child` descendants in `cards/half-height.less:92,143` & `cards/double-wide.less:51,87`; missing comma in `search.less:57-59` transition; selector typos `wrapper.less --83PercentContainier`, `rtl.less:170 &-selctedItemsQty`; mis-scoped rules leaking to all cards in `cards/news.less:26-51` & `cards/three-fourth.less:241`.

11. **The only near-BEM naming** is accidental: `categories.less` (`.filters-category`, `.filters-category--icon`, `.filter-group-title`) and `cards-carousel.less` `.modern-carousel--light` pair kebab blocks with `--` modifiers — the closest the repo comes to BEM, though both files are riddled with hardcoded colors and (in categories) a stray PascalCase `.Categories` block.

## 4. Recommendations

Because the audit standard (BEM) and the codebase convention (SUIT-CSS-style) fundamentally disagree, recommendations split into two tracks:

**Track A — Decision first (most impactful):**

- **Confirm the intended standard.** The codebase is coherently SUIT-CSS-style and shipped into AEM/DEXTER markup that references these exact class names. A true BEM migration (`.consonant-Card-inner` → `.card__inner`, `.is-active` → `--active`, etc.) would touch nearly every selector _and_ every consuming template — a large, breaking, cross-repo effort. If BEM is genuinely required, scope it as a dedicated migration with a class-name mapping and coordination with AEM authors; do not attempt piecemeal. If not, re-run this audit against **SUIT CSS** or the **existing convention**, which will produce an actionable punch-list instead of a wholesale mismatch.

**Track B — Standard-agnostic fixes (worth doing regardless of naming decision):**

1. **Correctness (broken/dead rules):** fix `&-element`-in-variant selectors (`three-fourth.less:90`, `text.less:87`, `double-wide.less:136,140,150,154`, `editorial.less:22-26`); bare `:only-child` (`half-height.less:92,143`, `double-wide.less:51,87`); missing comma in `search.less:57-59`; re-scope `news.less:26-51` and `three-fourth.less:241`; typos `wrapper.less --83PercentContainier`, `rtl.less:170`; undefined `@for-*` vars in `hide.less`; invalid `font-weight:light` (`type.less:27`), outline shorthand (`main.less:31`), `border:2px` (`card.less:83`).
2. **Theming integrity:** move `icon.less` and `horizontal.less` onto themeable `@consonantGray*`; replace hardcoded hex/rgba in `cards-carousel`, `categories`, `blade`, `editorial`, `button`, `flex`, `filters/*`, `pagination`, `select`, `accessibility` with tokens.
3. **Breakpoints:** replace raw-px/arithmetic queries in `cards-carousel`, `cards-grid`, `categories`, `blade` with named `@consonant-*-up` queries.
4. **Hygiene:** de-duplicate helpers across `utils/`/`references/`/`components/consonant/utils.less`; remove dead commented blocks (`lineclamp.less:15-37`, `utils.less`, `filters/left/item.less:476`); resolve the `categories.less` "should be moved" TODO; exclude vendor `modal.less` from future audits.
